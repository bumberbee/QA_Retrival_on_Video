# Security and reliability fixes

Branch: `upgrade/extraction-fixes`. No commit, push, or branch switch. No dependencies added.

## Verification and changes

| Defect | Verified? | Fix | Tests | Residual risk / limitation |
| --- | --- | --- | --- | --- |
| 1. `video_id` path traversal | Yes. Paths interpolated unchecked IDs; slide containment used the already escaped video directory. Transcript and review writes were vulnerable too. | Central `[0-9a-f]{12}` validation in storage; validation before cloud calls and before video/Q&A API work. Filesystem paths resolve under their fixed base, including symlinks/junctions. Extensions reject path injection. Nested slide paths remain supported. Local JSON writes now use an atomic replacement. | `test_storage_security.py`: every ID helper rejects `..`, encoded dots, backslashes, absolute paths, suffixes and glob characters; Windows junction containment; nested images; atomic-write failure cleanup. `test_api_security.py`: encoded URL attacks, including the reported Windows URL, and primary/cross-video Q&A IDs. | Storage directories must remain under the operator's control: a concurrent privileged process changing links after validation can still race a filesystem operation. `retrieval.py` is outside the authorized edit scope; its direct internal path helpers still need validation/containment if exposed elsewhere. Current video/outline/Q&A HTTP entry points validate IDs before invoking retrieval. |
| 2. Unauthenticated content writes | Yes. Upload, transcript replacement, slide review, and URL import had no admin gate. | Those four writes require `X-Admin-Token` when `ADMIN_TOKEN` is configured, using constant-time comparison. With an empty token, writes are allowed in local file mode and denied with 403 in cloud mode. Upload authorization happens before multipart parsing. Reads, Q&A, and browser-owned conversation history retain their existing contracts. | `test_api_security.py`: missing/wrong/correct tokens on all four writes; local empty-token behavior; cloud empty-token denial; public reads and Q&A; authorized cloud review against a mock database; upload denial before spooling. | A shared token grants all supported content writes; it is not a per-user login. The current frontend does not send this header. Use an admin client that supplies it, and keep the secret out of frontend build variables. Configure a token even in local file mode when exposing that server publicly. |
| 3. Unlimited/partial uploads | Yes. Uploads copied directly to their published filename without a limit or failure cleanup. | `MAX_UPLOAD_MB` defaults to 2048 MiB. ASGI middleware bounds the incoming multipart body to the file limit plus a 64 KiB envelope, checking both declared lengths and streamed chunks. The route independently counts file bytes, copies in 1 MiB chunks to a temporary file on the destination volume, then atomically moves it. Failures close streams and remove temporary, video and metadata files. | `test_api_security.py`: exact-limit success with no premature publication; unknown-size and HTTP oversize rejection; early declared-size rejection; read and persistence failures; chunked request rejection and closure of partial multipart spool files. | Concurrent authorized uploads can still consume disk/threadpool capacity. Multipart spooling and the staged destination copy briefly require approximately twice the file size. A process kill or machine crash can leave a temporary file; unfinished temporary names are excluded from the library. |
| 4. Cloud writes reported success while writing locally | Yes. `save_video_meta` and `save_transcript` always wrote files. URL import and upload consequently published unusable local-only data. | Storage rejects unsupported cloud writes. Upload, transcript PUT and URL import return a clear 403 even with a valid token. Import scheduling and its background worker also reject cloud mode before local writes. Cloud slide-review writes remain supported through the existing database adapter. | `test_storage_security.py`: direct cloud metadata/transcript rejection with no local files; supported cloud review call. `test_api_security.py`: authenticated cloud HTTP rejection before storage/download work; direct import rejection before scheduling. | Adding cloud upload/import/transcript editing requires explicit Supabase/R2 persistence and indexing support. Use the existing offline import/sync workflow for demo data. |
| 5. Blocking work inside async routes | Yes. Video handlers ran file I/O, ffprobe, synchronous database/object calls and import scheduling on the event loop. Q&A and conversation handlers were already synchronous. | Video handlers are synchronous `def`, so FastAPI runs them in its threadpool. Upload reads/writes and ffprobe execute there. Existing synchronous range iterators continue running in the threadpool. A lock keeps slide-review read/modify/write operations together across request threads. | `test_api_security.py`: a deliberately blocked library read runs concurrently with a successful health request; concurrent slide-review edits preserve both keys. Existing video import and byte-range tests pass after adapting direct calls to synchronous handlers. | Slow requests still occupy threadpool workers. The review lock protects this process; coordinating review writes across multiple workers would need database-level updates. |
| 6. Database deadlines | Yes. No explicit connect/statement deadline; pool acquisition relied on the library's default. | Configure libpq `connect_timeout`, PostgreSQL `statement_timeout`, and pool/acquisition timeouts. Defaults: 10 seconds, 30,000 milliseconds, and 10 seconds respectively. | `test_db_timeouts.py`: factory configuration, overrides, bounded connection acquisition and timeout propagation, with the pool mocked so no database is contacted. | These bound connection acquisition and individual statements, not total duration across multiple statements. Live database behavior was not exercised because the existing integration tests were skipped. |
| 7. Ollama streaming failures / missing terminal event | Yes. Only connection-opening `URLError` was handled; read failures, malformed NDJSON and premature EOF escaped or incorrectly completed. History persistence could also fail after generation without a terminal event. | Translate open/read transport failures, invalid UTF-8/JSON/schema, provider errors, empty answers and EOF before `done: true` into `LLMUnavailable`; close the response. Q&A emits a terminal `error` on failure and `done` on success, including history-save failures. Unexpected stream failures return a generic error and are logged. | `test_llm_reliability.py`: timeouts, reset/disconnect/incomplete reads, malformed bytes/JSON/schema, provider error, premature EOF, empty streams, successful final content, HTTP NDJSON error/done events and history failure. | The Ollama timeout is a per-operation socket timeout, not a total generation deadline. A disconnected client cannot receive a terminal event. Failures before streaming starts retain ordinary HTTP error behavior. |
| 8. Gemini parameters discarded | Yes. `_complete()` forwarded limits to Ollama but called `gemini.complete(prompt)` without them. The installed `google-generativeai==0.8.3` SDK supports the needed options. | Bounded rewrite/summary calls now pass `max_output_tokens` and `temperature` through `generation_config`, and `timeout` through `request_options`, using the existing Gemini configuration/model. | `test_llm_reliability.py`: rewrite and summary forward their distinct limits, temperatures and explicit timeouts to a mocked SDK model. | Timeout enforcement belongs to the SDK. Ordinary answer-generation methods keep their existing SDK defaults; this fix addresses the parameters accepted by `_complete()`. No change to the out-of-scope `gemini.py` was required. |
| 9. CORS origins | Partly. `CORS_ORIGINS` was already honored and the default did not use `*`; however, explicitly configuring `*` enabled it alongside credentials. | Ignore wildcard origin entries while retaining explicit configured origins and the existing localhost/loopback origin regex. | `test_api_security.py`: configured deployed origin, all three local address forms, rejected foreign origin, wildcard filtering, credential handling and admin-header preflight. | CORS controls browser access; the admin token enforces content-write authorization. |

## ID format evidence

`backend/scripts/import_fast_pipeline.py` looks up an existing video by its original filename and otherwise calls `storage.new_video_id()`. Source labels such as `L25_V011` and `MLS-15DA1` are filenames/pipeline labels, not app video IDs. The configured local library was inspected read-only: all ten IDs in videos, transcripts, keyframes and index directories use 12 lowercase hex characters (for example `0bc38ac7ee13`). No data migration is needed for that library.

## Environment configuration

Documented in `.env.example`, without a real admin token:

| Variable | Default | Meaning |
| --- | --- | --- |
| `ADMIN_TOKEN` | empty | Shared admin secret supplied as `X-Admin-Token`. Empty enables local content writes and disables cloud content writes. |
| `MAX_UPLOAD_MB` | `2048` | Maximum uploaded file size in MiB; must be positive. Incoming multipart data has an additional bounded 64 KiB envelope. |
| `DB_CONNECT_TIMEOUT_SECONDS` | `10` | Database connection deadline. |
| `DB_STATEMENT_TIMEOUT_MS` | `30000` | PostgreSQL deadline for each statement; positive values are enforced. |
| `DB_POOL_TIMEOUT_SECONDS` | `10` | Connection-pool acquisition deadline. |
| `DB_POOL_SIZE` | `5` | Existing setting, now shown in the example environment file. |

Set a strong `ADMIN_TOKEN` on the public demo backend, configure the exact frontend URL in `CORS_ORIGINS`, and restart the backend to apply middleware and pool settings. Changing the token does not enable unsupported cloud upload/import/transcript writes. Existing `OLLAMA_TIMEOUT_SECONDS`, `REWRITE_TIMEOUT_SECONDS` and `SUMMARY_TIMEOUT_SECONDS` remain supported.

## Validation

Baseline: 57 tests, 2 skipped. After changes: **100 tests, 2 skipped, no failures** (43 added tests).

```powershell
& backend/.venv/Scripts/python.exe -m unittest discover -s backend/tests -q
```

All new test modules import `_isolate` first. Filesystem mutations use temporary directories; new cloud and SDK tests use mocks and never contact Supabase, R2 or a real LLM. The two existing cloud integration tests remain skipped when their local test database is unavailable. Scoped `git diff --check` also passes. Existing concurrent edits in retrieval, Supabase, pipeline, frontend and documentation files were preserved.
